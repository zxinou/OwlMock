# JD 智能分析三态页面设计

## 目标

将当前单页内混合输入、全屏加载遮罩和简单列表报告的 JD 模块，升级为三个独立、可恢复的页面状态：

1. 输入页：`/analysis/jd`
2. 分析任务页：`/analysis/jd/tasks/:taskId`
3. 报告页：`/analysis/jd/:analysisId`

本阶段只实现纯 JD 分析，不引入简历匹配。简历匹配模块后续可以复用本设计的页面结构和视觉组件。

## 设计原则

- 保持现有 OwlMock 主视觉，使用墨绿、苔绿、金色和珊瑚红，不采用外部提示词中的紫色主题。
- 模型只返回结构化 JSON，前端负责渲染；不让模型生成 HTML、CSS 或页面配色。
- 不展示没有简历依据的“匹配度”。使用岗位难度、要求数量、技能权重和风险数量表达 JD 特征。
- 分析任务在后台运行。用户可以离开页面、刷新页面或切换模块，返回后继续查看进度。
- 保留文本 JD、图片 JD、历史记录和删除能力。
- 兼容已有 JD 历史记录，不重建现有表关系，不删除旧字段或旧接口。

## 页面设计

### 输入页

输入页使用一个紧凑的分析工作区，不同时堆叠文本卡片和图片卡片。

- 顶部显示“JD 智能分析”和历史报告入口。
- 使用分段控件切换“粘贴文本”和“上传截图”。
- 文本模式提供字数统计、输入校验和主分析按钮。
- 图片模式复用现有文件上传组件，支持 PNG、JPG、JPEG，限制 10MB。
- 桌面端右侧显示最近分析；移动端最近分析移到输入区下方。
- 点击历史记录直接进入对应报告页；删除使用项目内确认对话框，不调用浏览器 `confirm`。

### 分析任务页

任务页不使用 `LoadingOverlay`，页面导航始终可用。

- 显示岗位标题或输入摘要、总进度和当前阶段。
- 固定展示四个用户可理解的阶段：
  1. 识别岗位信息
  2. 拆解要求与技能
  3. 判断风险与面试重点
  4. 整理结构化报告
- 后端内部阶段可以更细，但前端映射到以上四步。
- SSE 可用时实时更新；SSE 断开后轮询数据库状态，不立即判定失败。
- 任务完成后自动替换到 `/analysis/jd/:analysisId`。
- 任务失败时在当前页显示错误说明、重试按钮和返回入口。

### 报告页

报告页使用全宽结构化 Dashboard，不保留输入页的固定历史侧栏。

- 报告头：职位、公司、地点、薪资、生成时间、岗位难度。
- KPI：硬性要求数、优先条件数、核心技能数、风险数。
- 要求区：硬性要求、优先条件和加分项，附原文依据与技能标签。
- 技能区：展示“核心 / 重要 / 加分”权重，不使用没有简历依据的百分比进度。
- 洞察区：隐含期待、风险及证据、具体准备建议。
- 面试重点：问题、为什么会问、准备方向。
- 猫头鹰总结：整体判断和 3-5 个摘要标签。
- 提供“分析新 JD”“返回历史”和删除命令。

## 视觉系统

所有页面使用项目现有 CSS 变量：

- 主操作：`--color-primary`
- 页面背景：`--color-base`
- 表面和弱强调：`--color-surface`、`--color-surface-alt`
- 主要文字：`--color-ink`
- 硬性要求和风险：`--color-accent`
- 优先条件：`--color-secondary`
- 正向状态：主色浅色背景配深色文字

卡片、按钮、间距和字体继续使用现有 Tailwind 扩展值。语义色仅用于风险、警告和完成状态。深色模式使用现有 token 自动切换，不新增写死的深色页面配色。

## 结构化报告

模型输出由 Pydantic 校验，核心结构如下：

```json
{
  "job": {
    "title": "",
    "company": null,
    "location": null,
    "salary": null,
    "difficulty": {"level": "高|中|低", "reason": ""}
  },
  "requirements": [
    {
      "category": "硬性要求|优先条件|加分项",
      "title": "",
      "detail": "",
      "keywords": [],
      "evidence": ""
    }
  ],
  "skills": [
    {"name": "", "importance": "核心|重要|加分", "reason": ""}
  ],
  "implicit_expectations": [
    {"text": "", "evidence": ""}
  ],
  "risks": [
    {
      "title": "",
      "severity": "高|中|低",
      "evidence": "",
      "suggestion": ""
    }
  ],
  "interview_focus": [
    {"question": "", "why": "", "preparation": ""}
  ],
  "recommendations": [],
  "summary": {"text": "", "tags": []}
}
```

缺失的公司、地点或薪资必须返回 `null`，不允许模型补造信息。旧记录的 `requirements`、`implicit_expectations`、`red_flags` 和 `suggestions` 由兼容转换器映射到新报告结构。

## 提示词调整

`JD分析报告_UI提示词.md` 只作为页面信息架构参考，不直接放入模型上下文，原因如下：

- 它要求模型生成完整 HTML，与当前 Vue 架构冲突。
- 它的紫色配色与 OwlMock 主色不一致。
- 它包含无简历依据的匹配度和技能百分比。
- 让模型生成样式会增加 token、延迟和输出解析风险。

后端 `jd_analyzer.md` 改为严格的结构化分析提示词：

- 只输出符合 Pydantic 模型的 JSON。
- 明确区分硬性要求、优先条件和加分项。
- 所有风险和隐含判断必须给出 JD 原文依据。
- 不生成简历匹配分数，不编造缺失信息。
- 输出 3-5 个岗位相关面试重点和可执行准备方向。
- 中文 JD 使用中文输出；非中文 JD 保持输入语言。

## 后台任务与接口

保留现有同步接口以兼容已有调用，新增前端使用的异步任务接口：

- `POST /api/jd/analyses`：提交文本 JD，返回任务信息。
- `POST /api/jd/analyses/image`：提交图片 JD，持久化输入后返回任务信息。
- `GET /api/jd/analyses/{id}`：返回状态、阶段、进度、错误和完整报告。
- `POST /api/jd/analyses/{id}/resume`：内存任务丢失时幂等恢复任务。
- `GET /api/jd/analyses`、`DELETE /api/jd/analyses/{id}`：保持现有路径和行为。

任务 ID 与 JD 分析记录 ID 相同。记录增加兼容式字段：`source_type`、`source_path`、`status`、`stage`、`progress`、`error`、`updated_at`。为避免重建 SQLite 表，现有非空 `result_json` 在任务完成前保存为空对象字符串 `"{}"`，完成后再原子替换为正式报告。

图片输入存储到后端目录之外的项目级缓存目录，避免 `uvicorn --reload` 因文件变化重启。文本输入直接保存在数据库记录中。服务重载后，任务页可以通过数据库状态发现 stale 任务并调用幂等恢复接口。

## 数据流

1. 用户在输入页提交文本或图片。
2. 后端创建 `pending` 记录并立即返回分析 ID。
3. 前端进入任务页并订阅任务状态。
4. 后端读取输入、调用带 fallback 的结构化模型、校验结果并保存。
5. 前端收到 `completed` 状态后进入报告页。
6. 报告页直接读取数据库结果，刷新或重新打开不需要再次调用模型。

## 异常处理

- 空文本、文本过长、图片格式错误和图片过大在创建任务前返回明确的 4xx 错误。
- 图片没有识别出有效 JD 时保存失败原因，并允许用户返回重新上传。
- 主模型额度不足时沿用现有 fallback；普通鉴权错误不伪装成可重试错误。
- 结构化输出校验失败时任务进入 `failed`，保留可诊断日志，不保存半成品报告。
- SSE 中断只触发轮询恢复；数据库明确为 `failed` 才显示失败页面。
- 删除正在运行的任务时先取消内存任务，再删除输入文件和数据库记录。

## 测试与验收

后端测试：

- 新结构化模型能验证完整报告并拒绝非法分类。
- 缺失岗位元数据保持 `null`。
- 文本和图片提交立即返回任务 ID。
- 状态和进度写入数据库，完成后保存报告。
- stale 任务可以幂等恢复，同一任务不会重复执行。
- Qwen 额度错误触发智谱 fallback。
- 旧 JD 历史可以转换并正常展示。
- 删除任务会清理关联输入文件。

前端和浏览器测试：

- 三个路由可以直接刷新和恢复。
- 文本与图片分段控件、输入校验和历史跳转正常。
- 分析时导航可用，不出现全屏遮罩。
- SSE 断开后轮询，完成后自动进入报告页。
- 报告所有模块在桌面和移动端无重叠、无横向溢出。
- 深色模式三个页面都可读，不出现空白。
- 删除使用项目内确认对话框。

## 本阶段不做

- 简历与 JD 的匹配评分。
- 简历模块 UI 重构。
- 导出 PDF、分享公开链接或多人权限。
- 重构 GitHub 分析与模拟面试模块。
